Medallion Architecture & Delta Lake Layering

The medallion architecture is a multi-hop data design pattern that logically structures data within an ACID-compliant Lakehouse into progressive quality tiers: Bronze (Raw), Silver (Curated), and Gold (Aggregated).

summarize Architecture TL;DR & Design Invariants
SPEC-0841
  • check_circle Bronze Invariant: Raw immutable append-only ingestion with source schema preservation. Never drop columns or fail raw batch streams.
  • check_circle Silver Invariant: Validated, conformed types, single-source-of-truth enterprise data models with stateful UPSERT/MERGE semantics.
  • check_circle Gold Invariant: High-performance read-optimized dimensional marts with sub-second OLAP scan rates for BI dashboards and feature stores.

The Three-Tier Lakehouse Mechanics

Traditional data warehouses forced a premature serialization of business logic during ingestion. Any upstream schema change broke daily ETL pipelines, causing cascade anomalies across downstream reporting tools. Lakehouse architectures utilizing the Medallion Pattern decouple raw retention from schema validation and dimensional aggregation.

By relying on open table specifications—most notably Delta Lake and Apache Iceberg—each layer executes atomic ACID transactions directly against inexpensive object storage like S3 or GCS, avoiding proprietary database lock-in.

warning Production Rule: Schema Enforcement vs Schema Evolution

Delta Lake enforces schema on write by default. In the Bronze layer, you must explicitly pass .option("mergeSchema", "true") to safely handle upstream API payload alterations without dropping unmapped attributes.

BRONZE LAYER RAW STORAGE

Append-Only Log

Retains 100% of the ingested state verbatim. Retains original payload timestamp and ingestion metadata.

Partition: date=YYYY-MM-DD
Retention: Infinite / Cold S3
SILVER LAYER CLEANSED

Conformed & Filtered

Deduplication via primary keys, strict type casting, timestamp normalization, and data validation rules.

Write Pattern: MERGE INTO (UPSERT)
Quality: Great Expectations
GOLD LAYER BI & ML READY

Dimensional Marts

Aggregated business logic, Star/Snowflake schemas, and pre-calculated feature tables for BI and LLMs.

Layout: Z-Order Clustered
Latency: < 150ms Pre-Agg
info Gotcha: Small File Problem & Auto-Compaction

Streaming micro-batches into Bronze generates thousands of 1-5MB Parquet slices. Always trigger OPTIMIZE silver_events ZORDER BY (user_id) nightly to coalesce small segments into standard 128MB-512MB columnar files.

MERGE INTO delta.`s3://lakehouse/silver/user_events` AS target
USING (
  SELECT 
    event_id,
    user_id,
    CAST(raw_payload:timestamp AS TIMESTAMP) AS conformed_timestamp,
    raw_payload:action::STRING AS status,
    sha256(raw_payload::STRING) AS row_sha256
  FROM delta.`s3://lakehouse/bronze/events`
  WHERE ingestion_date = CURRENT_DATE()
) AS source
ON target.event_id = source.event_id
WHEN MATCHED AND target.row_sha256 != source.row_sha256 THEN
  UPDATE SET *
WHEN NOT MATCHED THEN
  INSERT *;
